# Mortal rules 0.3.0: local encounter exclusion and referee recovery

This is a separate fresh-world authority profile, `mortal-rules/0.3.0`. It preserves `mortal-rules/0.2.0` bytes, APIs, rules and replay. No in-place database upgrade, mixed-version history, legacy snapshot adoption, world/branch migration or character/Fate authority integration is supported. A host must select exactly one writer/profile per world/branch. Existing v2 worlds require a separately designed authenticated continuation/cutover; regenerating a campaign would discard their progress and is not a migration.

The ordinary physical rules, bounds, direct-controller identity, capacity, supplies, light, death, rest, strict checks, initiative, turn order and disclosure rules in [the frozen v2 contract](../mortal-v2/CONTRACT.md) apply to fresh v3 data except for the explicit version, encounter exclusion, recovery, RNG/receipt domains and API changes below. They do not apply new meaning to v2 events. HP remains the sole health state; no invented alive/thread, consent, Fate or magical effect is added.

## Closed interface and explicit APIs

`packages/contracts/src/mortal-v3-types.ts` exports `MORTAL_V3_PROFILE` and the `MortalV3*` types, including `MortalV3ContractMap`, `MortalV3Ledger`, `MortalV3Action` and `MortalV3Encounter`. `packages/contracts/src/mortal-v3.ts` exports deeply frozen `mortalV3Schema`, `assertMortalV3Contract<K extends keyof MortalV3ContractMap>(name:K,value:unknown):asserts value is MortalV3ContractMap[K]`, `assertMortalV3Genesis(value:unknown):asserts value is MortalV3Genesis`, and `assertMortalV3Data(value:unknown):void`. The last performs only bounded passive-data inspection, not schema validation, authorization or authentication.

Each versioned Genesis, Command, State, Event, Receipt and ActorView requires exactly `mortal-rules/0.3.0`; v2 values are refused, not normalized. Principal and common physical data retain their existing structural shapes without claiming a version discriminator that they do not contain. Objects are closed and passive; no proxies/getters/exotics/cycles/sparse arrays/hidden properties, unsafe identifiers, noninteger/unsafe/-0 values or coercion. Maximum depth32/visits100000 and existing collection/clock/resource bounds apply. Validation does not mutate input. Both genesis entry points enforce full semantic initialization: clock0, initial positive HP, no discoveries/activity/rest/feeding debt, known references and initial capacity.

The separate future runtime module `packages/ledger/src/mortal-v3/index.ts` exports `initialMortalV3State`, `resolveMortalV3`, `mortalV3StateHash`, `mortalV3Capacity`, `createMortalV3Event`, `verifyMortalV3Event`, `replayMortalV3`, `verifyMortalV3Receipt`, `openMortalV3Ledger`, and `viewMortalV3Actor`. Their parameters/results are the corresponding `MortalV3*` types and otherwise mirror the v2 signatures. Opening takes `{path,genesis,privateKey,expectedHead?}`; `privateKey` is a host KeyObject, never JSON. `MortalV3Ledger` has asynchronous `snapshot`, bounded `events({after,limit})`, `submit(command,principal)` and idempotent `close`. No v3 export replaces the old API. Phase A freezes these interfaces; it does not claim runtime implementation.

## Single encounter, site and whole-roster exclusion

One encounter remains active per world. `begin_encounter` has the existing closed intent. Only the exact genesis referee principal, with null actor identity and matching complete rights scope, can create it. All participants must be unique, standing, co-located and within capacity. The authority records the common site as `encounter.location_id`. The entire original roster, including escaped, unconscious and dead members, stays at that site until closure. Store the same declared order, escaped/defended markers and round_participants as before. The selected current actor must be standing and not escaped.

All roster actors remain barred from ordinary out-of-combat actions until closure. Nonparticipants at the encounter site are also barred. A nonparticipant outside the site can perform ordinary actions only when no action dependency touches the site or its roster. In particular: remote travel must not arrive at the encounter site; give/transfer cannot target a roster actor; local trade/exploration/pickup/loot cannot consume site stock, opportunity or possessions. Normal resource, ownership, recipient and co-location checks still apply. Combat commands require the actual current encounter actor. A second encounter, even elsewhere, still conflicts. Joining sides, moving combatants, independent encounters and releasing escaped actors before encounter closure are unsupported.

Outsiders may read only their existing actor-scoped facts. No unrelated actor gains the encounter roster, others' numerical HP, hidden rolls, seed, inventories, referee recovery reason or privileged host history. ActorView retains the participant-only encounter summary. Its required `activity_lock` is null or exactly `{encounter_id,location_id,reason:'roster'|'site'}`. It is nonnull only when the viewer is personally locked: roster (including escaped members whose encounter summary is null) or a nonparticipant currently at the site. The lock location equals the viewer's own location. A visible encounter summary requires a matching roster lock. Remote actors get null. This reveals no roster membership beyond the viewer, other actors' private state or referee reason; it is not a complete forecast of all action availability (for example travel into a remote locked site still needs authoritative admission). No global encounter feed is added. Denial messages must not expose private encounter details.

## Time, pending round costs and RNG

`world_time` remains the sum of durations of admitted serialized actions. Only affected actors accrue `active_seconds`; remote activity does not spend combatants' provisions, advance their rest eligibility, expire defense or progress their turn. For example, after encounter creation at0, remote600-second travel produces world_time600 while its round/turn and participant active time remain unchanged. Completing or closing the pending combat round then produces world_time606 and charges6 active seconds to its frozen round_participants. Remote eight-hour rest similarly pauses the encounter locally. This is deliberate local pause, not simultaneous physical chronology or automatic catch-up.

No clock advances from reads, wall time, process restart, timeout labels or unrelated commits. Existing prepaid food/water assessments and death ordering apply to every positive active-time charge. Each completed round, including one ending mid-round, costs exactly6 seconds once; escaped actors in its frozen round_participants still pay that round, dead actors do not incur further needs, and earlier escapees stay excluded from later rounds. Reevaluate viable sides after costs. Refused commands change nothing, including RNG and token. Existing bounds are preflighted; recovery does not bypass terminal clock/history limits.

V3 uses the same HMAC-SHA256 rejection-sampling algorithm but the explicit domain `mortal-rng/0.3.0`. There is one global seeded RNG counter in signed total order. Remote hazard/exploration draws can change the later combat draw sequence relative to a different interleaving. Independent outcome streams, commuting histories and encounter-local RNG are not promised. The seed remains authority-only.

## Waiting-turn identity and referee recovery

`MortalV3Encounter` adds `turn_started_sequence`, an integer1..1000000 no greater than the state sequence. On begin, set it to the resulting event sequence. Update it to the resulting event sequence only when resolution selects the next active turn, including a round wrap back to the same actor; a turn is a specific occurrence, not merely an actor ID. Unrelated remote commits leave it unchanged. `location_id` and this token are required; every roster actor's location equals the fixed site. Sequence0 cannot contain an encounter.

The new closed action is:

```ts
{
  type: 'recover_encounter';
  encounter_id: string;
  turn_started_sequence: number;
  resolution: 'pass' | 'close';
  reason: string;
}
```

`reason` is nonblank and at most256 Unicode code points. `host_timeout` is a conventional trusted-referee attestation, not proof of elapsed time. No caller-supplied time, deadline, arbitrary outcome, dice, patches, side changes or target actor is admitted. Shape validation requires a null command actor, positive token not beyond expected sequence, exact action fields, and referee/null actor provenance when carried in an event. Runtime must also require the authenticated principal's exact genesis referee ID, null actor and full matching scope; shape alone cannot authenticate a principal.

The expected sequence/head and causation checks still protect every submission. At the verified current prefix, require the requested encounter ID and turn token to equal the actual waiting turn. This binding survives unrelated commits but rejects stale recovery after a real turn, round wrap, closure or reuse of an encounter ID. A referee cannot use a stale callback to pass a different actor simply by refreshing the global cursor. Recovery refuses absent encounters and corrupt state; it never repairs integrity failures.

For `resolution:'pass'`, use the ordinary current actor pass transition and ordinary finishCombat settlement: expire that actor's defense, advance to the next eligible turn, and charge no additional time while the same round continues. At round wrap or encounter end, charge exactly6 seconds once, including the usual needs assessments; then select the next round or close as normal. Preserve explicit referee provenance in the command/principal and a `referee_pass` effect identifying the affected current actor; do not impersonate that actor's consent.

For `resolution:'close'`, charge the currently pending round exactly6 seconds once to its frozen round_participants using the same needs/death rules, then clear the encounter. This includes closing immediately after begin before any ordinary turn, and closing immediately after the prior round settled (the new pending round still costs6). Emit `referee_close`, not a victory or player retreat. No extra damage beyond ordinary needs, attack, loot, heal, move, refund or award is added. The referee may close even when escape_allowed is false; that is explicit administrative authority, unavailable to players/NPCs. Close may spend supplies or cause starvation damage and must not be described as consequence-free.

Timeout detection/delivery belongs to an authenticated host outside the writer transaction. The deterministic engine does not read Date.now or trust a player's clock. Automatic machine-enforced deadlines, restart-safe timing attestations and clock rollback rules are not supplied. Every accepted recovery is a signed, replayable command; exact retries return the original receipt and do not re-pass/re-charge. A normal turn racing recovery resolves through existing cursor/CAS serialization. Reconcile an ambiguous submission with the identical request before creating a replacement.

## Signed history, storage and public trust

Events commit the full v3 genesis hash, scope, command, principal, before/after hashes, draws/effects and signature. Replay re-executes this v3 reducer and checks every derived field; no callback/model/clock is consulted. State hashes exclude only head. Event signature/hash rules remain otherwise identical. Receipt signatures use domain `mortal-receipt/0.3.0`, bind complete request/principal, authority key, scope and genesis; v2 receipt verification cannot accept them.

The v3 SQLite file is separate and uses `mortal_v3_meta` and `mortal_v3_events`, with immutable genesis and append-only journal/index. Refuse v2/mixed/foreign application tables, profile mismatch or genesis mismatch before mutation. Preserve asynchronous worker execution, bounded pending calls/replies/pages, WAL/FULL durability, transaction-level verified-prefix refresh, atomic unique request index/event/receipt commit, input detachment, exact retry binding and external expectedHead prefix checks. A prior verified row is trusted append-only within a handle; offline malicious DB/storage rollback requires the existing external checkpoint assumptions. Never run callbacks, a scheduler or model work inside BEGIN IMMEDIATE. Raw state/events/receipts are host-only; receipts may contain other actors' effects.

Host authentication, key provisioning, delivery, referee-session policy and writer exclusivity remain integration responsibilities. This profile provides no HTTP login, scheduler, deployment, UI, migration or paid model execution. Frozen v2 files and behavior continue to be checked independently.

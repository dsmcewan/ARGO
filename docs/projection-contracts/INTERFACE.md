All public functions perform descriptor-based preflight before canonical/clone/access: reject proxies (without invoking traps), accessors, decorated/sparse arrays, symbols, cycles and unsupported prototypes; depth<=32, nodes<=50000, total UTF8 string/key bytes<=8MiB across validated args, arrays<=4096. Then canonical-reject unsafe DTOs before cloning/access; runtime shape then semantic constraints. Context values must validate principal v1 and ReadPolicy/CommonCheckpoint; null policy UNAVAILABLE. Query, principal, both cursor scopes and policy.prefix scope exact rights namespace equality. policy.actor_id==principal.actor_id, actor_authorized true. Checkpoint request ID exact. Current policy prefix must dominate checkpoint seq/time; equal seq requires equal head/time, lower fails; trusted host must independently verify ancestry/freshness (seq dominance alone isn't cryptographic proof). All query times bounded by checkpoint prefix clock/sequence. Canonical valid time also >= genesis supported time? Context has no genesis min yet: add context.genesis_world_time:number mandatory safe nonnegative, <=checkpoint.world_time, and reject canonical valid<genesis_world_time; actor acquisition cutoffs also >=genesis time.
Actor query requires actor==principal.actor_id and party in trusted policy.party_ids for party audience. Canonical requires principal.role==='system' and policy.canonical_read true.

buildActorView validates bounded arrays, matching scope for ALL rows, unique claim_id and acquisition_id, source seq<=checkpoint prefix, acquisition tick<=checkpoint clock, claim occurrence<=checkpoint clock, source event identities syntactically valid (trusted projector verifies actual ledger linkage later). Every acquisition references an existing claim, claim source seq<=acq seq and occurred<=acq tick. Filter by exact knower, acquisition cutoffs and explicit party_id for party query, not union. Dedup same claim selecting earliest eligible seq/tick/acquisition_id; emit sorted claim IDs. Ineligible sources aren't leaked. Cutoff empty payload rule. V1 rows/event signatures never modified.
selectCanonicalRelations validates bounded rows and scope, unique revision IDs per relation; select recorded_from<=N<recorded_to and valid_from<=t<valid_to. Source genesis_ref must match checkpoint.genesis_ref; event source seq match recorded_from. Future revision rows can be skipped by recorded interval (needed retained-history read), never emit them. Reject multiple active revisions per relation. Return sorted relation/revision IDs. This is a reference selection/guard, not graph storage/materializer.

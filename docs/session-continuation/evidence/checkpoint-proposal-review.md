# Checkpoint proposal interface review

2026-11-14. Read-only review of `/workspace/ARGO/.worktrees/session-continuation` at `de737c5db88042db2150f47d6dc4e0280e80ba96`. This assesses the recommendation, not an implemented checkpoint system or an implementation authorization. No source changes, tests, providers or subagents were used.

The proposal is consistent with the current authority boundary after two wording corrections now present in `docs/session-continuation/CHECKPOINT_BOOT_PROPOSAL.md`: it describes an existing deterministic **condition**, not an existing commit subscription, and distinguishes the externally anchored checkpoint prefix from later acknowledged events. No further factual blocker found in the recommendation. The following limits must carry into a future versioned design.

1. **A checkpoint reference protects a floor, not every later acknowledgment.** If checkpoint N is externally anchored and events N+1 through M are subsequently acknowledged, restoring the local store to N passes a checkpoint-N check. Detection requires a separately retained, authenticated expected acknowledged cursor `{sequence, head, world_time}` covering M, checked against the restored archive and suffix. Merely having an external service is insufficient if it still records N. Current `expectedHead` already checks those three fields against an exact committed ancestor (`packages/ledger/src/world/storage-worker.ts:70–75`; `SYSTEMS/shared-world-v1/CONTRACT.md:142,148`). The proposal's revised line 27 states this distinction correctly. Do not restore the earlier claim that an independent latest-checkpoint reference alone detects every lost acknowledged prefix. Future acceptance should explicitly test “checkpoint N; acknowledge M>N; restore N; checkpoint-only reference accepts the floor, expected-M reference refuses.” An all-acknowledgment guarantee additionally needs an explicit durable external-reference acknowledgment protocol; asynchronous anchoring leaves a stated exposure window.

2. **The encounter trigger is exact, but wiring it is new work.** Verified `physical.encounter !== null` to `=== null` is correct. Mortal `finishCombat` emits `encounter_end` when combat becomes nonviable; this may follow attack, defend, retreat, pass or referee pass. `recover_encounter` with close emits `referee_close`, advances time and clears the encounter (`packages/ledger/src/mortal-v3/rules.ts:210–218,263–271`). Mythic disengagement is separate and does not itself mean the physical encounter ended. Effect text alone is not authority. `WorldEvent` carries before/after hashes, not both states; `WorldLedger` has only latest `snapshot()`, paged `events`, `submit`, and `close` (`packages/contracts/src/shared-world-types.ts:67–77`). A snapshot fetched after receipt N can already be N+1. The future publisher therefore needs an exact verified immutable prefix and recoverable, idempotent trigger processing. Proposal line 7 now accurately says those APIs do not exist.

3. **512 is an initial tuning heuristic, not a measured service limit.** Count newly committed sequences since the last accepted checkpoint, not world-time elapsed: speech and other social actions can advance sequence without advancing time. There is no automatic threshold or expedition-checkpoint command today. Suggested small clarification at line 5: “a periodic threshold, initially 512 newly committed events as a tuning heuristic.” Benchmark publication cost, suffix length, restart latency and failure recovery before choosing a default.

4. **Archiving events does not compact the current authoritative state.** `State.memories.length` must equal the sequence, with contiguous memory provenance; the state hash includes the full memory history (`packages/contracts/src/shared-world.ts:130–147`). The aggregate 16 MiB / 500,000-value / depth-32 data bounds and complete 16 MiB RPC bound still apply; collection maxima are not achievable capacity guarantees (`shared-world.ts:23–42`; frozen contract line 146). A checkpoint of today's State can speed replay but still grows with history and cannot silently discard memories, request deduplication or actor provenance. The proposal correctly reserves retrieval-index compaction for another versioned representation. The RNG seed belongs to complete genesis and the evolving counter to physical state; both must remain bound to the same private checkpoint identity.

5. **Retiring hot event payloads requires archive-aware storage semantics.** Today one SQLite event row contains the event, request identity/hash and original signed receipt. Exact retries read that row and validate its command/principal/receipt binding before new-request stale checks. Event paging, expected-prefix checks and warm-prefix verification also read old rows (`packages/ledger/src/world/storage-worker.ts:30–43,70–97`). The current schema forbids event updates/deletes and rejects extra application tables (lines 55–65); cold open starts from genesis. A future archive store must preserve old exact retries, conflict detection, historical pages, receipt-prefix lookup and full audit replay before any payload retirement. This is a versioned storage change, not a usable maintenance operation on the current database.

6. **Preserve privacy, time and recovery boundaries.** Raw State/events and checkpoints remain host-private. Views use exact actor/principal scope and cursor, committed acquisition and validity times, current closure/revocation, and full-history reply provenance; the returned last 32 memories/impressions are only a bounded view, not an archive substitute (`packages/ledger/src/world/view.ts:8–34`). Keep permanent offer/request identities, original receipts, historical speech and already-issued obligations even when current knowledge access changes. The private conversation outbox is a separate durable store: its “separately bound recovery position” still needs a future consistent-cut/reconciliation definition, rather than assuming one world snapshot atomically captures both stores.

The no-model-wait recommendation is correct. Existing storage publishes its owned state cache only after COMMIT (`storage-worker.ts:46–49`), and the frozen contract forbids models, callbacks or schedulers under the writer transaction (line 144). A future checkpoint publisher can work from a captured committed immutable prefix while later commits and model calls continue; it must not convert a pending model proposal or outbox entry into world truth. Current fast boot remains unimplemented, and the measured 2,000-event verified open remains 13.88 seconds with the under-ten-second target unmet.

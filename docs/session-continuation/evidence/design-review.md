**Verdict: READY for implementation within the documented scope; no remaining design blockers.** The six-phase design is a suitable bounded implementation plan. Fixed principals, separate worker-owned outbox, irrevocable persisted dispatch intent, permanent generation marker, generic `no_reply`, fresh player disclosure and explicit local rollback limits address the main failure modes. No new approval flow or scope expansion is needed. The following findings were resolved during review; their original substance is retained for implementation acceptance.

## Resolved findings

**Important — post-commit receipt rejection must not be classified as definite admission failure.** `DESIGN.md:42` permits definite failures to settle but does not specify how they are identified. `packages/session/src/index.ts:72-73` awaits `ledger.submit` and then validates the signature and exact request binding; these checks can throw `UNAUTHORIZED` or `INVALID_CONTRACT` after an event has committed. Those codes are also used for pre-dispatch/admission errors. A host that treats every non-`UNAVAILABLE` error as definitive can mark an actual commit rejected and abandon reconciliation. Require a trusted admission-origin result or exact journal/request reconciliation; otherwise retain or halt the same pending command after any post-dispatch error. Do not replace its request ID or reprepare. Add a real-commit-then-malformed/foreign-receipt control, followed by restart and exact retry, to the acceptance cases. This can be resolved in the session/host implementation without changing the frozen journal contract.

Resolved in `619f124a82cff818abff730248ac4d60acf421ed`: the design now expressly prohibits error-code-only classification, retains ambiguous pending commands, requires pre-dispatch proof or exact prefix reconciliation, and names the commit-then-bad-receipt control.

**Minor — pin the existing memory-ID grammar explicitly.** `DESIGN.md:27` groups request IDs and memory IDs as being derived from versioned domains and world/actor/turn identity. Host request IDs may use that new grammar, but canonical memory IDs must remain exactly `hash({domain:'shared-world/0.1.0/memory',genesis_hash,request_id,sequence})` (frozen CONTRACT §identity; `rules/engine.ts:143`). Actor/turn identity is carried indirectly by the derived request ID; adding fields or a host-specific memory domain makes scoped lookup fail and conflicts with the unchanged-authority requirement. State that hosts obtain/verify the authority's memory ID, using its committed sequence, without changing its preimage. No extra API is required.

Resolved in `425b152b350bf55cfab149a02bab263415e89e16`: request IDs alone use the new host domain; the exact frozen memory preimage is now written explicitly.

**Minor — scope the permanent-attempt guarantee to one canonical outbox.** `DESIGN.md:23,25,40,56` promises one adapter invocation per turn and asks for “two-store simultaneous claims.” Two processes/handles over one SQLite file share the marker; two independently initialized files do not. Both can reconcile the same deterministic player request and then invoke the adapter before canonical NPC reply dedup chooses a winner. Specify one canonical private outbox per configured conversation identity, or explicitly limit the invocation guarantee to callers sharing that store. Acceptance should say two independent worker connections/processes to that same file. Separate-file creation/loss/rollback stays within the stated local-storage limitation; a global registry or bus is unnecessary. Canonical one-reply-per-inbound still belongs to the ledger.

Resolved in `425b152b350bf55cfab149a02bab263415e89e16`: the design scopes the guarantee to processes sharing one canonical outbox, acknowledges independent-file limits, pins the CLI file to fixed player/NPC/policy identity, and corrects the concurrency acceptance wording.

## Confirmed design boundaries

- The adapter-versus-HTTP distinction at `DESIGN.md:23` is accurate: `routeCall` iterates configured pools and `maxAttempts:1` limits attempts per pool. This corrects any overly strong reading of “one invocation” in the earlier recon: the durable marker bounds calls to the adapter, not all transport requests inside that call.
- Pending phases may complete an event after cancellation because dispatch intent was already persisted. Cancellation suppresses later generation/disclosure; it does not promise rollback. Late generation results must lose their CAS after cancellation/expiry/recovery, and cancellation must also be checked at the final disclosure boundary after async player-view acquisition. This is implementation acceptance of the existing invariant, not another public API requirement.
- `read` must remain effect-free with respect to generation, and terminal reads must not return cached NPC text after closure or memory eviction. Explicit unknown generation outcome and generic `no_reply` are truthful with the current adapter API; a tagged silence API is unnecessary for this scope.
- Cold reconstruction retains the frozen guard as differential oracle, exact generic hash preimage, immutable forks and every historical verification step. Its local timing target does not justify dropping checks. The plan's dependency order and source-review/application-gate distinction are consistent.
- Package dependency/exports can be finalized within the documented ownership: the new session constructor will use interventions/model types, so its package dependencies must be updated with the coordinator's lockfile. This is already covered by SC-620 package ownership, not a design blocker.

No authority re-audit, runtime acceptance or performance result is claimed by this review. The findings are small specification clarifications, with the first protecting a concrete crash/recovery ambiguity exposed by the current API.

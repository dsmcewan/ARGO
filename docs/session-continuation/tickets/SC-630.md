# SC-630 — explicit offline conversation CLI

Start only after SC-620's source and public API are accepted/integrated. Read DESIGN.md, TURN_CONTRACT.md and the implementation. Own `scenarios/tempted-fates/shared-world/cli.ts`, its README, and new `TESTS/shared-world-conversation-cli.test.ts`. Root owns status/acceptance and manifest/lock changes outside these paths. No nested agents, paid/network calls, Board writes, merges or pushes.

Preserve existing init/resume/demo and low-level operations. Add `talk-init --dir WORLD --actor PLAYER --npc NPC --fixture FILE` for exclusive outbox creation and `talk` with the same flags for open-only operation. Derive exactly WORLD/turns.sqlite; never recreate a missing store during open or vary its path to evade a binding mismatch. Existing private world validation and signing/ready files remain controlling. One fixed conversation binding per world directory is an explicit CLI limit.

Use closed fixture JSON `{version:'shared-world-offline-fixture/1.0.0',fixture_id,turns:[{turn_id,player_text,reply_text}]}`, at most 256 entries/one MiB, unique IDs and exact actor-bounded text (reply may be null). Pin the complete canonical fixture and fixture-adapter version through the host's resolved policy ID. No trimming, interpolation, fallback response, SDK, credential discovery or arbitrary module loading. Immutable per-attempt client factory metadata selects the fixture; verify actual focused context/actor/input before returning the selected strict text/null response. Identical input text under different turn IDs may have different fixtures; no mutable ambient current-turn selection.

Closed JSON-line operations are talk `{op,turn_id,text}`, continue/status/cancel `{op,turn_id}`. Precheck known fixture IDs and exact input BEFORE any host dispatch. Map directly to host turn/resume/read/cancel; do not reimplement phases or disclosure. Emit only public host results with `mode:'offline_fixture'` and validated fixture identity. Every new-mode output/error is labeled. Never print private prompt/row/proposal data. Repeated reads use the host's player projection and may suppress committed text after closure/eviction.

Await bounded output across all CLI paths, preserving existing injected sinks that return array lengths. A callback-backed stdout Promise supplies backpressure. Cap fully encoded output including wrappers/newline; do not truncate. A sink failure stops admission of more input and propagates rather than being treated as an action error or recursively written to a broken sink. Close host, then store, then caller-owned journal in finally paths.

Tests: private create/open/refusal and binding changes; unknown/mismatched fixture before any side effect; restart, same-ID retry, cancellation and non-driving status; repeated input with distinct turn fixture selection; actual scoped context and response preservation; no physical/loan effect; player closure/eviction suppression; held/rejected emitters and byte limits; existing CLI compatibility. Ordinary subprocess tests clear NODE_TEST_CONTEXT and use private regular-file stdin/stdout/stderr descriptors. Use the actual host/store implementation. Source worker runs targeted checks and commits; independent review and unchanged application gate remain separate.

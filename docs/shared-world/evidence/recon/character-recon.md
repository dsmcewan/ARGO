# Character, dialogue and authored knowledge recon for one shared world

Baseline inspected read-only: `3fd1e4d99eede6853f62b8078e5921183a9f048c` in `/workspace/ARGO` (2026-11-14). No repository edits, migrations, paid model calls or new workers. This report distinguishes existing implementation from proposed successor design. No new runtime tests were run for this reconnaissance.

## Coordinator decision received after inspection

The coordinator selected a fresh `shared-world/0.1.0` authority with one global cursor; its physical payload omits duplicate sequence/head/time. New `WorldActorView`/`WorldMemory` types avoid the frozen legacy action enum, and a new world adapter reuses model-client plumbing. Initial sessions include ordinary mortals only; Fate and donor-time transactions remain in their frozen legacy profile until explicitly ported. A monotone, exactly authenticated referee `close_mythic_engagement` action protects the cutoff without inventing Fate authority.

The new `WorldProfile` deliberately uses nature, activity and max_speech_characters rather than silently copying legacy minimum_interval. Speech is zero-time; a host may plan one NPC reply per incoming record and authority/replay enforces the same unique `(npc_id, in_reply_to)` invariant. This explicit successor policy resolves the legacy60-second cooldown mismatch. Existing profiles remain unchanged. This design is consistent with the inspected boundaries.

Require in_reply_to to identify an actually acquired addressed speech record; mere visibility is not a direct summons. Commit reply uniqueness atomically with the accepted speech. The closure check must apply at admission and before/after generation; no late or explanatory ontological output is released once closed. This is not a new blanket ban on all earlier mythic scene description.

Knowledge catalog/source identity guards are reusable, but current activation/read types embed CharacterActorQuery. New WorldKnowledge bindings or an explicitly reviewed compatibility adapter are still needed; do not cast a new world query into the old type. The older compatibility suggestions below are fallback analysis, superseded by the coordinator's explicit new WorldActorView/WorldMemory choice.

## Recommendation

Create one fresh versioned shared-world authority with one actor registry, one current sequence/head/world_time, one signed event stream, one request-ID index and one SQLite transaction per accepted command. Reuse mortal pure mechanics and character admission/projection semantics behind that writer. Do not instantiate both `openMortalV3Ledger` and the legacy `createCharacterAuthority` for the same world/branch, synchronize two journals, replay invented carriers, or regenerate an existing world and call it migration.

The existing model-backed NPC agent is a proposal-only planner and is a good reuse target. Its current wire guard cannot represent every unified event honestly: the frozen character action enum excludes mortal actions and accepted bargains. A complete combined milestone therefore needs an additive context/event adapter version, not mutation of frozen character1.0 or mortal0.3 schemas. A limited speech-only compatibility projection can reuse the old agent during bring-up, but must explicitly admit that it omits physical/bargain memories; it is not the finished milestone.

## Identity, clock and contract mismatches to decide before coding

1. **Actor registry:** legacy actor maps use IDs, `alive`, Fate role and thread state but no immutable controller mapping. Mortal actors have `{id,controller_id,kind:'player'|'npc',location_id,hp,...}`. Bind an immutable controller/role record once in shared genesis and use the same actor ID for speech, impressions, knowledge owner, physical actions and bargains. Reject cross-profile aliases and collisions; use the stricter shared ID bound (mortal campaign IDs max64 versus character max96). System/referee capabilities must be separate authenticated identities, not actors inferred from model labels.
2. **Roster:** `scenarios/tempted-fates/runtime-v3.ts` builds fresh mortal genesis by `buildMortalCampaign` from runtime.ts. The latter excludes NPCs with a Fate role and all loom locations. `campaign/catalog.ts:211 buildCampaignSeed` includes all Fates plus a system actor and traveler party. Do not blindly zip these arrays. Map by exact ID; either limit this headless milestone to mortal NPCs and preserve explicit unsupported Fate actions, or add distinct nonphysical Fate identities/jurisdictions deliberately. Do not give Fates invented mortal HP just to satisfy a join.
3. **Cursor zero:** CharacterCursor is `{sequence,head:string|null,world_time}` with head null iff sequence0 (`contracts/characters.ts:45`). MortalV3State starts sequence0/head=hash(genesis) and keeps world_time outside its cursor. A compatibility adapter must explicitly map only the presentation zero cursor to null while pinning shared genesis separately; do not change the shared canonical head. A new shared wire cursor can avoid this mismatch entirely.
4. **One sequence:** resolveMortalV3 increments sequence itself and checks exact expected head and immutable genesis. A new outer reducer cannot simply keep an independent mortal sequence/head alongside character events. For reuse, derive the mortal input slice at the outer sequence/head and record one resulting global sequence, with an explicit, tested nonphysical-event path. At genesis the embedded mortal state's genesis hash/head binding also needs an explicit definition. Never sign an inner mortal event then sign a second character event for one interaction.
5. **Health:** mortal hp>0 standing; hp==0 unconscious survivor; hp<0 dead. `alive` alone cannot express speech eligibility. Preserve `alive = hp>=0` if retaining its biological meaning and add a standing/can_speak check before generation and at append. Setting alive=false for unconscious actors changes meaning; leaving it true and relying only on old agent permits useless model calls and invalid speech proposals. Atropos/ended-thread authority is separate and absent from mortal-v3; one life model needs explicit reconciliation before enabling it.
6. **Time:** current character speech/impression/activity/configuration consumes no world time. Mortal actions add their declared durations; remote activity does not charge encounter participants active time. Many campaign NPC speech policies require60 seconds between accepted utterances. A zero-time conversation cannot produce repeated replies without deliberate clock progression or an explicitly selected speech policy. Do not advance clocks from reads, provider latency or wall time; do not charge a full exploration turn by accident. A new positive-duration speech policy also requires new receipt rules because the old bridge requires unchanged time.
7. **Action memory grammar:** `CharacterExperience.action_type` is a frozen enum: move_item, record_consent, revoke_consent, transfer_time, grant_proxy, revoke_proxy, vanish_thread, name_anomaly, end_thread. It cannot carry travel, attack, buy, transfer_item, offer_bargain or accept_bargain. Records must have strictly increasing source sequence, so two separate experiences at the same global event sequence are also invalid. Define a successor discriminated event reference/summary or a single truthful compound summary, with deterministic IDs for subrecords if those are needed. Do not relabel a bargain as legacy move_item or a physical action as somebody's speech merely to pass validation.

## Minimum coherent read/planning adapter

Proposed files, not implemented: `packages/contracts/src/shared-world-types.ts`, `shared-world.ts`, `packages/ledger/src/shared-world/characters.ts`, `packages/lexi-bridge/src/shared-world.ts`, and a small explicit shared-context entry in interventions. Keep frozen old profiles available for their old worlds.

- One trusted reducer produces shared state containing the physical slice plus character profiles, accepted speech, witnessed action summaries, acquisitions, impressions, authored-knowledge registrations and cutoff state. These are materialized caches of the same committed history, not separate authoritative tables/services.
- Expose a pure `projectSharedCharacterState(sharedState)`/`viewSharedCharacterActor(sharedState,query,principal)` and scoped narrator counterpart. Derive life, location, cursor and world time from canonical shared fields rather than duplicate mutable copies in the character projection.
- Reuse `createCharacterViews` selection policy: authenticate direct viewer/full scope, require exact current head/time, choose latest impression per observer+subject, filter acquisition before limiting, select latest16 by first acquisition and emit source order. An old event first witnessed now becomes recent; repeated grants do not refresh its recency. Party membership alone never shares private solo knowledge.
- For the initial compatibility path, existing CharacterView can hold genuine shared speech records and legacy-supported action records only. For complete accepted-bargain/physical awareness, dispatch a new validated view version through the same model packet/budget/freshness machinery. Avoid changing the declared old coverage to imply omitted actions are present.
- Obtain shared room facts from verified current actor location plus explicit perception/rights policy, then use the authored room description. Do not use NPC seed occupancy as current position. Dynamic weather/room changes need canonical shared records at this cursor, not private opinions promoted into room facts.
- Use one registered authored catalog identity and recorded activation in the shared authority. Read the persisted activation from that reducer, verify ancestor membership using the shared prefix, and build the existing exact-query grant for the compatible cursor. The offer view remains separately labeled authored policy. The current sidecar API can remain as a pure projection when its query shape is compatible.
- Wrap/dispatch model output back into a shared speak/impression proposal. The single writer revalidates expected shared cursor, actor controller, standing status, cutoff, budget, witness grant and impression evidence. There is no call to the old character writer, old observe_claim carrier or mortal store in this path.

## Witness and belief provenance

Existing character speech stores the authenticated speaker, exact accepted text and an explicit host witness grant bound to request_hash. The speaker is added as witness. Each acquisition carries its own sequence/time/party; later witness_action records current acquisition time, not original source time. Impression evidence must concern its subject, be acquired by its owner, use the current nature revision and match its predecessor ID. Keep these semantics.

The callback runs before the writer lock, then the current head/authorization is rechecked. In the new profile, bind witness authorization to full shared request/principal/scope/cursor and store the accepted host attestation inside the signed event. Delivery addressed_actor_ids is not evidence of hearing, and party membership is not evidence of presence. Seed room occupancy grants nothing. Optional empty external witnesses means self-only; unknown/dead recipients or stale attestations fail. Never expose grant internals, hidden RNG or complete physical effects to NPC context.

`observation-admission/1.0.0` now supplies a useful exact-request/attempt/expiry callback pattern, but remains transient legacy ingress authorization, typed to legacy Snapshot/IntentProposal. It explicitly does not persist witness evidence in old events. Do not claim replayed historical observations gain stronger provenance merely because the new admission callback exists. Prefer native shared speech/witness envelopes with durable authority provenance.

## Offers versus accepted bargains and physical custody

The only current loan record is authored `offer_policy`. Its first-person implication and structured terms establish what Melia may offer, not an active authorization to take her item. There is no accepted-bargain reducer, obligation table, due-checkpoint state or actual-damage adjudication in ledger/contracts. `MortalV3Action.transfer_item` requires the current holder's direct controller, living co-located recipient and capacity. It does not bind recipient acceptance, loan policy, return terms or legal title. `buy` atomically exchanges obols for stock but is not bilateral NPC bargain acceptance.

Minimum new canonical transaction:

1. An authenticated lender posts a bounded, revocable offer with exact lender/borrower IDs, item, curated policy hash, explicit proposed terms/return checkpoint, validity and nonce at the current shared cursor. Merely presenting the catalog creates no offer.
2. The addressed borrower accepts that exact active offer/term hash with a new authenticated request. No prose parsing, model statement or inferred consent counts. Lender authorization can come from the recorded still-valid offer; no impersonation of lender by a referee is implied.
3. In one deterministic writer transaction, recheck life/standing, current custody, co-location, encounter locks, capacity, expiry/revocation and unchanged terms. Append one event recording accepted bargain and any agreed handover together. Either both commit or neither does. Exact retry returns the original receipt; concurrent offers cannot transfer one lamp twice.
4. Record the lender's retained loan relationship, borrower, explicit checkpoint and repair cap separately from physical holding. Mortal `owner_id` currently means the actor holding an item for admission purposes; changing it for a loan must not silently assert legal title passed. Keep that distinction explicit in new shared types.
5. Project a bounded witnessed acceptance/handover summary into each entitled participant's memory from that same event. Canonical accepted terms and current custody remain physical/transaction facts, not mutable offer policy or observer opinion. Private impressions about the bargain remain separate.

A deterministic `return`/`cancel` path can then refer to the same bargain ID and enforce current holder/co-location/locks. Damage bills, unilateral price changes, compulsory work/oaths, automatic debt or time donation are not licensed by this ordinary lamp transaction. Exact source terms: no fee/deposit; replacement/repair cap5; repair actual damage by agreement; oil1 obol/6 exploration turns; explicit return, normally next agreed harbor return; no compulsory service/oath.

## Cutoff and model limits to preserve

Legacy cutoff is global within world/branch: any vanished thread sets ontology_blocked; naming any anomaly also closes engagement (`characters.ts:189–190`). Existing authoritative speak rejects either cutoff; NPC planner returns null before provider/supplement lookup; model refresh discards late output; narrator returns empty records/no continuation. Mortal-v3 has no cutoff state. The new shared profile must explicitly carry/project cutoff from the same signed history and reject stale output, or explicitly leave Fate/anomaly actions unsupported. It must not default false by omission when importing existing state. No narrator principal, room entry, tone choice or alternate persona reopens the cutoff.

Model adapter bounds at baseline: timeout default10000ms/range1..60000; max input32768 UTF-8 bytes/range1024..131072; combined output default2048/range1..8192; one attempt per candidate/pool, at most8 candidates; low effort; empty replay history; no tools, streaming or continuation allocation. Speech obeys actor configured Unicode max (campaign Melia240); impression output at most2048; raw response max32768 bytes; exact JSON {text:string|null}. Null is silence. It refuses incomplete/refusal/tool output. Context includes one definition per nature revision, incoming acquired speech once, only the interlocutor's current impression, selected authored offer and explicitly granted room. Refresh before attempts, after async counting and after generation includes view+supplement fingerprint. Cache scope uses full tenant/rights/world/branch plus actor/task and packet.version. Reuse all of this in the shared adapter; never let a generated bargain claim become accepted authority.

## Acceptance tests for this milestone

- One global signed sequence/head through interleaved travel, speech, offer, acceptance, custody and impression; fresh replay gives identical physical/character/bargain projections and restart returns the same views.
- Exact controller/actor mapping: outsider cannot speak as Melia, lend her lamp or accept for traveler; no alias or cross-rights-scope joins.
- Atomic acceptance/handover, stale and revoked offer refusal, duplicate request idempotency and two concurrent borrowers: exactly one custody success, no partial obligation or transfer.
- Disclosure: lender/borrower receive only their witnessed summary; private solo facts do not enter party raid context merely by membership; later witness acquisition cannot backdate knowledge.
- No duplicate mutable time/location/life: travel changes scene at same cursor; unconscious/dead actors cannot generate or commit speech; cutoff during provider delay suppresses reply and append.
- Ordinary authored policy remains distinct from accepted terms; source pins, activation time and grant revocation survive restart as shared-state projections.
- New action memory grammar can faithfully name accepted bargain/physical actions; no fabricated legacy carrier, action type or attributed speech; old frozen replay and DTO tests still pass.
- Existing deterministic output/input/token budgets and one-call/no-tool behavior pass with injected providers only. No paid run needed.

Repository status at inspection was clean. The recommendations above are design work for a fresh successor profile, not evidence that ARGO already has unified authority, accepted bargains or persistent host activation.

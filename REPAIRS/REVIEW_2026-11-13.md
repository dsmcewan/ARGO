# ARGO research, structure and implementation review

Reviewed commit: `a9745e72e93d82c72e87f5159edd5c59f4c426c0`.

The research and broad architecture are coherent, but the current implementation needs another hardening pass before unattended parallel builds. Two P1 findings affect merge acceptance and preservation of local data. Further P2 findings concern recovery, component boundaries and model-client behavior. Green CI did not cover the reproduced cases below.

This was a read-only repository review using six topic-specific peer reviews, source and primary-document checks, and targeted disposable probes. No repository source, schema, database or GitHub branch was changed. No paid vendor calls were made. The report itself is outside the repository. P1 means fix before unattended use; P2 means fix before expanding the affected component; P3 means lower-priority compatibility, scaling or documentation work.

## What held up

- Primary sources support the inspected licensing distinctions for Knave 1e, Cairn, Blades, D&D SRD 5.2.1 and OSE. Year Zero applicability remains explicitly unresolved because the full license was inaccessible; Knave rule bytes/fixtures remain unpinned. These are declared limitations, not new defects.
- The signed gameplay file ledger and the SQLite build board are separate systems. The current LEXI snapshot mock is distinguished from the proposed persistent graph stores. Causal/epistemic separation, explicit observer filtering and acquisition-time/sequence checks are present in the implementation.
- Frozen v1 hashes and generated types reconciled. The 840-blob/525-module totals and the 25 SQLModel table declarations reconcile with the catalogs. The separate “114 model classes” label needs correction below.
- Active Pantheon uses the shared model-client implementation and canonical registry symlink; no active import of the historical `pantheon-seat-core` mirror was found in the inspected paths.

## Findings requiring implementation changes

### R01 — P1: Trusted merge controller omits the newer acceptance checks

[controller/merge.mjs:29](/workspace/ARGO/controller/merge.mjs:29), [scripts/gate.mjs:15](/workspace/ARGO/scripts/gate.mjs:15), [CI workflow:27](/workspace/ARGO/.github/workflows/deterministic-gate.yml:27).

The controller neither protects the new board/research test policy nor runs those checks. CI runs them as separate steps, but the controller does not require a passing CI result. In a disposable clone, replacing `tools/board.py` with an immediate `RuntimeError` still passed the trusted controller and advanced the target to that broken candidate. The controller returned 0; the merged board returned 1.

This does **not** show that CI would accept the broken board. It shows that the documented trusted-controller path can integrate it without those checks. Add the new acceptance suites to the controller's required gate, pin their trusted oracles/policy, and require actual test completion. A reviewed trust-policy update is needed. Retained evidence: [probe result](/tmp/argo-review-controller-result.json), [controller log](/tmp/argo-controller-review-eyt81nqo/controller.log), [probe script](/tmp/argo-review-controller-probe.py). The real repository was not the merge target.

### R02 — P1: Board merge overwrites ignored local files

[tools/board.py:685](/workspace/ARGO/tools/board.py:685), [tools/board.py:747](/workspace/ARGO/tools/board.py:747).

`_clean_target()` uses ordinary Git status, which omits ignored paths. If a candidate adds a tracked file at an ignored path that already contains local data, the later `read-tree -u -m` overwrites that data. A real Git/SQLite/Bubblewrap probe produced `MERGED`, an advanced HEAD and a valid audit chain while replacing existing `feature/local.txt` bytes with candidate bytes.

Check incoming additions against existing untracked paths, including ignored files and relevant directory collisions, before updating the target ref. Preserve/refuse collisions explicitly in both normal integration and recovery.

### R03 — P2: Recovery loses integration intent if recovery itself is interrupted

[tools/board.py:768](/workspace/ARGO/tools/board.py:768), [tools/board.py:729](/workspace/ARGO/tools/board.py:729).

`recover()` stores `already_integrated` only in a local variable and replaces the durable `MERGING` state with `VERIFYING`. A second interruption loses the information that Git already contains the candidate. The reproduced sequence was `MERGING → interrupted recovery/VERIFYING → REVIEW → merge retry/READY`, while HEAD already equalled the candidate, the child stayed BLOCKED and no accepted artifact handoff appeared.

Persist integration intent/head independently of the verification state until acceptance completes. Recovery must be repeatable across multiple process failures, not only the initial merge failure. The reproduction used real confined gates; only interruptions were injected.

### R04 — P2: Autonomous subscribers bypass checkpoint expiry and supported-policy checks

[packages/interventions/src/index.ts:6](/workspace/ARGO/packages/interventions/src/index.ts:6).

The subscriber checks checkpoint shape, scope, actors and view equality, but omits expiry and the v1 policy restriction. An untrusted planner can return a handwritten proposal instead of using the guarded proposal helper. Through the real subscriber/TELOS/ledger path, each of `expires_at == world_time`, `policy: queue` and `policy: transparent_fork` committed a lamp transfer.

Reject invalid/expired and unsupported checkpoint contexts before invoking the planner, and apply the required invariants to returned proposals. Helper functions cannot be the only enforcement point for untrusted planners.

### R05 — P2: Accessor array entries can substitute private knowledge after validation

[packages/contracts/src/index.ts:24](/workspace/ARGO/packages/contracts/src/index.ts:24), [packages/lexi-bridge/src/index.ts:20](/workspace/ARGO/packages/lexi-bridge/src/index.ts:20).

The canonical validator rejects accessor object properties but permits accessor array slots. Validation reads an array getter; the subsequent `structuredClone` reads it again. A synthetic injected transport returned an authorized claim during validation and an outsider-only claim during cloning. The bridge returned that frozen outsider claim; revalidating the returned DTO rejected it.

This concerns in-process object transports: ordinary JSON-decoded responses cannot contain getters. Reject accessor/non-data array entries and validate the exact detached object that will be returned or used. Review other validate-then-clone boundaries for the same pattern.

### R06 — P2: TELOS outcomes are not bound to the complete scope/proposal

[packages/telos-bridge/src/index.ts:13](/workspace/ARGO/packages/telos-bridge/src/index.ts:13), [Outcome schema:1328](/workspace/ARGO/SYSTEMS/argo-v1.schema.json:1328).

`Outcome` has neither a full scope nor a digest identifying the complete submitted proposal. The bridge checks ID, sequence, time, action type and event kind only. An actual outcome from an open-license ledger was accepted by a private-upload bridge when those fields matched: the local ledger stayed at sequence 0, the foreign ledger reached 1, and the bridge returned the foreign hash as success.

This is response misbinding through a wrong/misrouted injected transport, not a bypass of the ledger's incoming scope checks. Bind the response to scope and proposal identity, with an appropriate authority verification rule. Because the wire schema is frozen, this requires a reviewed versioned contract change.

### R07 — P2: An older success erases a newer credential-pool refusal

[packages/model-client/cooldown.mjs:39](/workspace/ARGO/packages/model-client/cooldown.mjs:39), [router.mjs:47](/workspace/ARGO/packages/model-client/router.mjs:47).

The router unconditionally calls `success(pool)`, which deletes the pool's cooldown. In an offline concurrent probe, request A started first and waited; B received 429 with `Retry-After: 120`; A then succeeded and deleted B's future cooldown. Request C immediately invoked the provider. Filesystem locking serializes writes but does not preserve the order of request/refusal events.

Fence success cleanup against newer refusals using a revision/generation or comparable request identity. Recheck shared cooldown state before retries as well. This is material before multiple workers share a usage pool.

### R08 — P2: Google full token-count requests misplace allowed options

[packages/model-client/client.mjs:39](/workspace/ARGO/packages/model-client/client.mjs:39).

The full-count converter leaves `toolConfig` and `safetySettings` inside `generateContentRequest.generationConfig`. The pinned Google SDK places them at the generate-content request root. An injected recording fetch confirmed the actual count and generation wire bodies differ this way for otherwise allowed options.

Correct the count-request conversion and compare the serialized envelopes in a regression. This was an offline serialization finding, not a live-provider 400 test; the malformed preflight can prevent generation when these options are used.

### R09 — P3: Public TypeScript declarations lag the model client's exports

[packages/model-client/index.d.mts:5](/workspace/ARGO/packages/model-client/index.d.mts:5), [package.json:11](/workspace/ARGO/packages/model-client/package.json:11), [index.mjs:2](/workspace/ARGO/packages/model-client/index.mjs:2).

A temporary strict TypeScript consumer could not import runtime exports `prepareRequest`, `checkBudget`, `compactConversation`, `classifyFailure` or `COMPACTION_BETA` from the package root (TS2305). Advertised `/request` and `/router` subpaths produced TS7016 because declarations are missing. Supply matching root/subpath declarations and verify a consumer through the package's public exports.

### R10 — P3: Identifier contracts accept names the state-map codec rejects

[IntentProposal schema:508](/workspace/ARGO/SYSTEMS/argo-v1.schema.json:508), [mechanics.ts:90](/workspace/ARGO/packages/ledger/src/mechanics.ts:90), [contracts/index.ts:30](/workspace/ARGO/packages/contracts/src/index.ts:30).

`proposal_id: constructor` passes the proposal schema, then fails when it becomes a key in `Snapshot.proposals`: `Unsafe canonical property`. No event commits. Align identifier restrictions with dictionary-key restrictions at the contract boundary, or use a representation that accepts the documented identifier domain. Preserve fail-closed behavior while making the contract accurate.

### R11 — P3: The allowed 1,000-ticket DAG can exceed Python's recursion limit

[tools/board.py:383](/workspace/ARGO/tools/board.py:383).

Initialization permits up to 1,000 tickets but recursively walks dependency chains. A valid 1,000-ticket chain ordered toward the next ticket raises unhandled `RecursionError`. Use iterative cycle/topological validation or an accurately enforced lower depth limit. The current 11-ticket seed is unaffected.

## Integrity decisions before graph/import expansion

These two P2 findings concern stronger integrity assurance at storage/import boundaries. Neither demonstrates a remote gameplay caller changing canonical state.

### R12 — P2: A signed head does not identify the complete genesis

[packages/ledger/src/mechanics.ts:112](/workspace/ARGO/packages/ledger/src/mechanics.ts:112), [replay:125](/workspace/ARGO/packages/ledger/src/mechanics.ts:125).

Events bind scope, ruleset and authority key but not a genesis digest. Standalone replay accepted changing an untouched donor's initial balance from 1,000 to 9,999 while using the same signed events and original expected head. The resulting balance changed without changing that head.

`openLedger` correctly rejects supplied/file genesis mismatches; this finding concerns replay/import verification, where the signed event history alone cannot establish which otherwise-valid genesis belongs to it. Bind or independently authenticate the genesis identity before export/import and graph rebuilds rely on the head as a complete state-history identifier. A schema migration may be required.

### R13 — P2: A complete journal-prefix rollback restores revoked authority

[packages/ledger/src/index.ts:43](/workspace/ARGO/packages/ledger/src/index.ts:43), [replay call:52](/workspace/ARGO/packages/ledger/src/index.ts:52).

Reads check internal chain validity but do not compare against a separately trusted monotonic head. Removing the complete final revocation record from a disposable journal changed sequence 3 to 2, restored `revoked: false`, and allowed a subsequent proxy action. Partial-tail checks do not detect removal of complete valid records; the snapshot is intentionally a derived cache.

This requires authority-storage write access or rollback/restore, not a gateway exploit. Decide whether this failure belongs to the supported threat/recovery model. If rollback detection is required, retain an independently trusted checkpoint/head and reconcile restores against it; otherwise document the storage trust assumption explicitly. Hash chaining alone does not provide that assurance.

# Deterministic merge controller

`npm run gate` runs one acceptance policy for both CI and the merge controller: frozen schemas and generated types, package boundaries, TypeScript, foundation/replay tests, the complete board/dispatcher Python suite, research Python and JavaScript tests, research package validation, and the full offline Pantheon/model-client suite. All checks are required. The gate hashes the candidate before and after execution; `--merge-ready` additionally requires a clean committed tree. Model review cannot replace these checks.

For worker merges, run `controller/merge.mjs` from a separately trusted checkout. Bind `ARGO_CONTROLLER_TRUSTED_SHA` to an operator-approved immutable commit outside the candidate workspace and pass `--repo`, `--candidate`, and `--trusted`. A candidate cannot choose or update that binding. The controller checks a clean target, compares extracted paths/blobs/modes/symlinks with the raw Git tree, rejects unsafe symlinks, and checks the trusted policy before installing or executing anything. Archive substitutions, omitted files and submodules are refused.

`acceptance-policy.mjs` pins the controller, scripts, test oracles, workflow, contract-freeze hashes, dependency/workspace manifests, and the **entire `tools/` control plane**, including board and dispatcher production code, support modules, tests and file inventory. Research Markdown and flat `findings/*.json` reports can change; its remaining files and directory inventory are pinned, including validators, schemas, manifest and any Python/native/bytecode import surface. New import packages or shadow modules are refused. The research test directory is never added to Python's import path.

The Python control plane must be trusted before its in-process tests run. A Python parent parses expected unittest IDs without importing application code, then checks the child's exact successful IDs, test count and normal completion receipt. This catches accidental import/body `os._exit(0)`, missing assertions, skips and failed tests. **It cannot authenticate results from hostile imported Python:** such code shares the child's interpreter and can forge its receipt. Consequently board/dispatcher changes require independent review and an explicit trusted-policy update; an ordinary worker candidate cannot modify them. The R01 regression demonstrates receipt forgery under the earlier permissive boundary and refusal before import under the repaired boundary. The runner's explicit `--trusted-import-root` option is used only for the fully pinned tools directory (and disposable test fixtures).

The JavaScript parent parses trusted test declarations, binds passes to exact source files/locations, and requires each test process's native normal-completion summary with no failures, cancellation, skips or TODOs. Repeated dynamic tests cannot substitute one pass for an early exit in another iteration. Printed success text, duplicate names elsewhere, and a zero process exit are insufficient. These are completion guards, not isolation from arbitrary interpreter/protocol tampering. The supported Python suite format uses explicit top-level test-class methods; dynamic/inherited discovery requires a separately reviewed runner change.

Dependencies install with lifecycle scripts disabled. Set `ARGO_NPM_CACHE` to a prepopulated cache for fully offline installs. The gate then runs inside network-isolated Bubblewrap with the entire staged candidate read-only, temporary files confined to `/tmp`, and no host repository or board database mounted. Read-only staging protects oracle ancestors as well as files. The Python child has a bounded deadline and combined output/receipt caps; the gate bounds each check and the controller bounds the whole isolated gate. Missing isolation support refuses execution.

After all checks pass, the target must still have its original HEAD and a clean checkout. Integration uses `git merge --ff-only --no-overwrite-ignore` for the exact tested candidate. An incoming tracked path cannot silently replace an ignored local file: Git refuses and preserves the target ref and bytes. The controller does not read model approval text.

Protected policy changes, including this repair and later board repairs, require a separately authorized trust-root update and independent review. They are never overlaid for testing and then merged as different bytes. Contract changes separately require a versioned migration; the frozen gameplay v1 files remain unchanged.

CI runs the same complete gate on push/pull request. Required-check and branch-protection enforcement remain GitHub repository settings; a workflow alone cannot prevent an administrator bypass. Local `npm run gate` reports checks on its checkout; only the separately trusted controller applies this candidate-versus-policy boundary and authorizes a worker merge. No repository setting or deployment is implied.

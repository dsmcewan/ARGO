# Mortal v3 runtime

This directory implements the frozen [mortal-rules/0.3.0 contract](../../../../SYSTEMS/mortal-v3/CONTRACT.md) for fresh worlds. Its explicit API is in `index.ts`; it never selects v3 by inspecting or upgrading a v2 database. All v2 source and replay remain separate. A host must select one profile/writer per world and branch. Existing campaigns need a separately designed continuation or migration.

The pure reducer and signed journal are host capabilities. Authenticate the caller and complete rights scope before constructing a principal. Possession of JSON with `role: 'referee'` is not authentication. The reducer checks that the injected referee identity matches immutable genesis; player/NPC controllers cannot recover encounters. Actor disclosure uses `viewMortalV3Actor`, not host state, events or receipts.

One encounter locks its complete original roster and site. Other actors can continue ordinary actions outside that site. Escaped roster actors remain locked until closure; `activity_lock` makes this visible even when their participant summary is hidden. Remote travel cannot enter the site, and remote transfers cannot touch the roster. Local ownership and co-location checks still apply to every other action dependency.

`world_time` is the sum of admitted serialized durations. Remote travel/rest advances that clock and only the remote actor's active time; it does not progress or age the paused combatants. A pending combat round costs exactly six seconds at wrap or closure. Shared HMAC RNG draws also have one serialized order, with the v3 domain: remote random actions can alter later combat draws compared with a different interleaving. This is not simultaneous chronology or independent encounter RNG.

A referee recovery command binds both the current expected cursor and the encounter's `turn_started_sequence`. Refreshing a cursor after a remote commit is permitted because that commit does not change the waiting turn token. Refreshing it after an actual turn change cannot reuse the old token. `pass` runs the ordinary current-turn settlement; `close` charges the pending six-second round once and clears the encounter. Both preserve referee provenance. Close can spend provisions and cause ordinary needs damage; it never refunds costs, heals, moves actors or awards victory/loot.

The host detects and attests a timeout outside the transaction. The engine does not inspect wall time or verify elapsed time from `reason: 'host_timeout'`. There is no automatic scheduler or timeout service in this module.

`openMortalV3Ledger` uses a dedicated SQLite worker, bounded calls/pages/replies, WAL/FULL durability, append-only v3 tables, and atomic event/receipt/request-index commits. An exact authenticated command/principal retry returns the existing receipt, including after close or restart; changed content or identity under that request ID conflicts. On ambiguous failure, reconcile that identical request before issuing a replacement. `close()` drains admitted calls and is idempotent.

`expectedHead` is an external trusted **ancestor** checkpoint, not a claim that this is the latest head. Opening accepts it only if that sequence/hash is in the fully verified current prefix; a newer valid descendant is allowed. An absent, divergent or rolled-back checkpoint is refused. Sequence zero must match the supplied genesis hash. The host must preserve/update its trusted checkpoint outside the same rollback domain as the database if rollback detection is required.

Within a live handle, the worker rechecks metadata and the cached head, then verifies only appended rows in the transaction. It trusts already verified rows to remain append-only. Page and retry reads rebind event bytes to the signed receipt. A privileged offline editor or rolled-back storage exceeds that live-cache assumption; reopen verifies complete history and the external checkpoint provides the separate rollback anchor. Existing foreign/v2/mixed tables and mismatched genesis are refused before journal-mode/schema/metadata changes.
